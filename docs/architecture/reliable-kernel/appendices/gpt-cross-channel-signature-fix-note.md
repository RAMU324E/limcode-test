# GPT 跨渠道推理签名与断流重试修复

## 生效边界

- 仅普通 OpenAI Responses 请求，来源和目标均为 GPT 系模型，且渠道配置 ID 不同，才隔离旧推理签名。同名模型跨渠道也属于此范围。
- 同渠道不隔离，包括同模型重试、模型切换、解密失败、超时或断流后重试；不增加错误触发的签名清理兜底。
- 非 GPT 模型、其他协议、来源不明或来源有歧义时保留原签名。GPT 识别支持数字型号、命名空间和方括号渠道前缀，不根据渠道名称猜测模型类型。
- 只过滤出站消息中的 `openai-responses:` 推理签名，不改正文、工具调用 ID、工具参数及结果，也不清理其他协议的签名或原生压缩密文。

## 来源与存储

来源通过现有 `ContextSegmentSource → MessageRevision → ModelRequestMessageLink → ModelRequest` 关系读取，仅使用模型原始输出修订；手工编辑后的未知签名不猜测来源。

物化时复用现有分批查询和关联索引，传递临时来源元数据。没有新增持久化字段、数据库迁移或会话修复写入。规划和实际发送使用同一过滤规则；原始 CAS 内容保持不变，切回原渠道仍能保留其签名。

## 断流重试

将 `peer closed connection without sending complete message body (incomplete chunked read)` 识别为可恢复的连接中断。沿用冻结的自动重试开关、次数、取消和 Attempt 边界；只替换尚未提交的模型输出，不直接重跑已经提交的工具效果。

## 回归覆盖

- 同名 GPT 跨渠道、带渠道前缀的模型、切回原渠道。
- 同渠道解密报错及再次重试仍保留签名；非 GPT、未知来源和其他协议不受影响。
- 正文、工具配对、其他协议签名、原生压缩密文和冻结历史不变。
- 工具成功后断流，按配置重试但工具只执行一次。
- 首次请求加四次重试后恢复或终止；关闭自动重试时只请求一次。
